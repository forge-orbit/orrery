# Runner CLI origin pinning, host-authenticated target discovery, and two-tier checkout bindings

Making `orrery-runner` zero-flag to start from any local checkout (#229) builds on [ADR-0010](0010-local-agent-runner-and-live-streaming.md) and [ADR-0011](0011-runner-harness-catalog-and-dispatch-options.md) while introducing four lasting security, identity, and contract commitments that must not drift across future CLI or server changes.

Once a **Runner host** is enrolled (`runner-credential.json`), its canonicalized server origin is authoritative for every credentialed command (`start`, `work`, `init`). `--server` (taking precedence over `ORRERY_URL` when explicitly passed) and `ORRERY_URL` act as origin assertions rather than silent overrides: if the effective asserted origin disagrees with the enrolled origin, `orrery-runner` fails fast before constructing an HTTP client so the long-lived host credential (`orr_rh_...`) can never be sent to an unintended host. Only `orrery-runner login --server <url>` may switch origins (printing a warning naming the replaced enrollment and reminding the human to revoke the old Runner host; multi-server credential storage remains intentionally out of scope). All credentialed Runner HTTP clients (`OrreryClient`, stream spool flush, and `/mcp`) refuse HTTP redirects (`redirect: "error"`), and plain `http://` outside loopback (`localhost`, `127.0.0.0/8`, `[::1]`) is rejected unless explicitly opted into via `ORRERY_RUNNER_ALLOW_INSECURE_HTTP=1` (with a per-invocation warning naming the origin).

Checkout identity is split into two distinct SHA-256 digests so convenience bindings never break server-side **Runner** concurrency isolation. The server-facing `repoFingerprint` hashes the real path of the checkout's `git rev-parse --show-toplevel` (preserving byte-for-byte compatibility at a repository root while giving each linked git worktree its own distinct `runners` row so two concurrent processes cannot collide on `registerRunner` upsert and reset `activeSlotCount`). Local remembered bindings in `~/.config/orrery/repos.json` (`0600`, atomic temp-file rename, keyed by `(canonicalServer, bindingFingerprint)`) hash the real path of the canonical main checkout root (the first `worktree ` entry from `git worktree list --porcelain`, which works uniformly for main checkouts, linked worktrees, and submodules) so linked worktrees inherit the main checkout's project binding without sharing Runner identity. A local per-`repoFingerprint` PID lockfile (`O_CREAT|O_EXCL`) prevents accidental duplicate `start` processes in the same checkout. Plain SHA-256 is kept rather than introducing a salted HMAC so existing `runners.repo_fingerprint` rows remain valid without migration; stronger path-pseudonym hardening is explicitly deferred.

Human-readable CLI flags (`--workspace`, `--project`, `--agent`) and the interactive picker are backed by a single host-authenticated read endpoint (`GET /api/runners/targets`, `Cache-Control: no-store`) returning the enrolled human's non-suspended **Workspace**s (including those with zero actionable projects so CLI errors can distinguish "no Contribute projects" from "not found"), their non-trashed `Contribute+` **Project**s, and their installation-wide, human-scoped **Agent**s (top-level, never nested per workspace) plus `defaultAgentId`. Name/slug/key resolution and ambiguity errors happen client-side over this live-filtered payload, while `POST /api/runners/register` remains strictly UUID-only and authoritative for live RBAC inside one transaction — allowing `start` with a valid saved binding to skip `GET /api/runners/targets` completely. Stale bindings (`401` revoked host, `404` `workspace_not_found`/`project_not_found`/`agent_not_found`, or `409` `no_default_agent` on registration) are never auto-deleted because **Trash** is restorable for 30 days; `hostId` stored in a binding is informational only (since every re-enrollment creates a new `runner_hosts` row) and never overrides live server RBAC. Adding a second server-side `resolve-target` endpoint or accepting workspace/project names directly on `POST /api/runners/register` was rejected to keep the OpenAPI surface minimal, avoid duplicate ambiguity semantics, and preserve clean Go/Rust portability.
